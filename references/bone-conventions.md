# VRM 与 PMX 人体骨骼约定

本文件供骨架规划阶段读取。表格表示语义对应，源骨真实名称以 VRM Humanoid 元数据为准；不要要求骨骼恰好叫 hips、upper_arm.L 等。默认使用本 skill 的骨架配置；用户显式选择其他体系时，再确认语义和扩展范围。

## 1. 姿态与命名

**先把 VRM 常见 T-pose 转换并固化为目标 A-pose，再重命名、改变层级和构建控制骨。** A-pose 必须同步作用于全部骨骼、网格及形态键。参考肩臂方向和手掌朝向，不复制参考人物的肢体尺寸，不硬编码下放角度。

表中 `.L/.R` 是 Blender 内部人体侧别命名；PMX 导出的日文名通过 `name_j` 等插件属性设置为 `左…/右…`。例如 `腕.L` 对应 `左腕`，不是把 `.L` 字面作为 PMX 标准侧别。已有日文全名人体骨按语义复用后统一内部后缀，不生成两套同义骨。

注意全角 `ＩＫ`、全角手指数 `０１２３` 与半角形式的差异。识别时允许经确认的别名，写入时选定一致规范并检查唯一性。`人指` 与某些模型的 `人差指` 需按参考实际名确认。

## 2. 躯干、眼睛和四肢

源完全没有眼骨且选择保留形态键眼控时，使用 `eye_mode="morph_only"`，省略左右眼和両目并检查眼控 Morph 保留；其余人体必需骨不变。

左右侧行均展开为两根实际骨。左右按角色解剖侧识别，不按观察者屏幕位置猜测。

| VRM Humanoid 语义 | 常见源名示例 | 目标 Blender 名示例 | PMX 日文名 | 位置与注意事项 |

## 4. 生成的控制骨与可选扩展

以下控制骨通常没有直接对应的 VRM Humanoid 项，按目标体系生成或复用已有有效控制骨。控制骨通常不承载蒙皮；不要把 hips 权重转给センター或全ての親。

| 骨 | 位置规则 | 层级 / 功能 |
|---|---|---|
| 全ての親 | 角色中线与地面附近的约定原点；标准化角色坐标下通常为原点 | 模型控制根，不继承参考展示偏移 |
| センター | 中线，按腰部锚点和目标参考相对偏移适配 | 全ての親之下，身体整体控制 |
| グルーブ | 中线，按目标参考的腰部关系适配 | センター子级，承接腰控制 |
| 腰 | 以上半身 head 为锚点、髋宽为尺度，位于后方略低处 | グルーブ之下，同时控制上下半身；见 [腰方案](waist.md) |
| 腰キャンセル左/右 | 对应大腿 head，保留髋关节支点 | 下半身之下、大腿之上，对腰设置 -1 付与旋转 |
| 両目 | 相对本角色头部和双眼中心布置 | 按参考挂接头部控制链；双眼附加旋转倍率取实际计划，不固定 0.4 |
| 足IK親.L/R | 对应脚的水平位置、地面附近 | 全ての親之下，作为脚 IK 父级 |
| 足ＩＫ.L/R | 本角色踝关节的静置位置 | 足 IK 親之下；腿两节 IK 目标 |
| つま先ＩＫ.L/R | 本角色实际脚尖，与足首尾端和つま先头部重合 | 足 IK 之下；脚部一节 IK 目标，显示向下 |

控制数量按腰取消系统、实际脚链和眼控方案确定。已有等价无权重控制骨先复用，避免重复；不得按总骨数判断结构完整。

| 可选骨 | 采用条件与限制 |
|---|---|
| 操作中心 | 用户或目标模板需要时生成；位于角色中线，明确与全ての親的职责和层级 |
| 腕捩 / 手捩及辅助捩骨 | 本流程默认按[次标准扭转规则](arm-twist.md)建立左右系统及各三根分配骨；配置固定轴、付与旋转、局部权重及求值顺序，不能仅重命名 |
| 足D / ひざD / 足首D | 采用兼容 D 骨体系时成套设计其驱动、变形顺序与蒙皮归属 |
| 足先EX | 承担脚趾变形及原 toes 权重；head 保留原 toes 关节支点，tail 与 head 等高并水平向前略超过同侧つま先/つま先IK头部，长度按角色几何和参考适配。父级采用足首或所选扩展的足首D；另保留独立つま先末端，不重复分配权重 |

是否采用D骨与是否拆分脚尖端点分别决定。源toes带权重时，复用为足先EX并保留权重，保留原 toes 关节 head，仅将 tail 向前延长至略过脚尖控制点，再另生成つま先；不能因缺少D骨而省略脚尖端点，也不必机械复制整套D骨。参考专属附属骨跳过，源角色附属骨保留。

脚部区分：`足首`是踝支点，`足先EX`承载原 toes 权重并从原脚趾关节支点旋转，`つま先`是独立脚尖末端，`つま先ＩＫ`是控制目标。按参考及真实脚部几何构造足首尾端与末端关系，不把脚趾根误当脚尖，也不沿旧斜向尾端随意延长。

脚部必需位置关系（角色Z向上）：

- `足IK親.tail = 足IK.head = 足首.head`；亲骨头部在地面，尾部接踝点。
- 足IK保持水平，从踝支点朝脚后跟；head 固定在踝点，tail 沿踝到脚尖的水平反方向延伸。长度按参考适配，不沿足首斜向脚尖，也不交换端点移动目标。
- `足首.tail = つま先.head = つま先IK.head`；该点在实际脚尖，足首贯穿整个脚部。
- つま先显示方向向上，つま先IK向下；足首→つま先和足IK親→足IK→つま先IK的层级正确。
- 源 toes 的带权重骨复用为足先EX；`足先EX.head = 原 toes 关节 head`；`つま先.head = つま先IK.head = 足首.tail` 是独立脚尖控制点；EX tail 沿水平前方略超过该控制点。
- 足先EX朝前、足IK朝后：在角色空间将踝到脚尖向量投影至水平面，足先EX的 head→tail 与其同向，足IK与其反向；足先EX两端等高，つま先与つま先IK的 head 重合，EX head 保留原关节，EX tail 的前向投影略超两个控制点。构建和回读均检查方向、水平及静置外观。

以上关系在构建和PMX回读后都要数值核对，不能仅凭骨名、总数或动作可求解判定完成。

## 5. 位置、层级与轴向约定

身体大部分关节位置来自源模型**固化后的 A-pose**，参考主要提供控制结构、相对锚点和旋转习惯。不同人体比例不能通过直接复制参考坐标解决。

基础层级示意（左右侧分别展开，实际肩臂挂点和眼睛控制层级按参考确认）：

```text
全ての親
├─ センター → グルーブ
│  ├─ 上半身 → 上半身2 → [上半身3] → 首 → 頭
│  │                └─ 肩 → 腕 → ひじ → 手首 → 各手指链
│  └─ 下半身 → 足 → ひざ → 足首 → つま先
├─ 足IK親.L → 足ＩＫ.L → つま先ＩＫ.L
└─ 足IK親.R → 足ＩＫ.R → つま先ＩＫ.R
```

VRM 通常是 hips → spine，PMX 常是上半身与下半身从腰部控制链分支。变换此层级时保持每骨目标 Rest 世界关系，不能仅换父级造成双重变换。hips 的功能可以复用，但其起点、朝向不必等同于目标下半身。用腰部语义锚点适配，保留本角色髋关节位置。

本 skill 默认生成或复用腰及左右腰取消。上下半身 head 在躯干起点相邻，下半身 tail 朝骨盆，上半身 tail 朝胸部；二者共同以腰为父级，不设置 use_connect 强制吸附到腰 tail。腰取消插在下半身与大腿之间，具体相对位置和作用见 [腰方案](waist.md)。

下半身方向由实际 head/tail 确定，roll 按骨段适配。记录已确认布局在上半身 Rest 坐标系中的归一化位置及局部轴，供构建和回读检查；跨角色时结合源关节适配。腿与裙子等子骨的静置支点保持不变。

下半身改向使用编辑模式的 Rest 操作，独立于 T→A-pose 烘焙；保存并恢复子骨 Rest 矩阵与骨长，保持绑定网格、形态键和权重。Rest 坐标系改变不代表角色应随之旋转，不对顶点施加新旧 Rest 的差矩阵。

全ての親、センター、グルーブ、可选操作中心应处于角色自身中线。只有坐标已标准化时中线才可直接写作 X=0；不要用参考模型所在世界 X 值。

骨骼局部 Y 为 head→tail，局部 X/Z 由 roll 决定。比较方向必须先统一空间；比较轴向使用完整矩阵和正交基，不能单比 roll 数字。参考轴运输只用于对应身体骨；附属骨保留 A-pose 后的轴向。膝轴根据实际弯曲平面确定，左右均需动作验证。

人体骨主要保留关节连线并适配 roll；控制骨还需匹配参考 head→tail 方向。足IK、脚尖IK和中央控制不能只对齐 roll 而保留相反的骨段方向。修改后确认静置外观和蒙皮保持一致。

PMX 固定轴、局部轴、显示连接与 Blender 编辑骨尾端不是同一概念，分别记录。启用固定轴或局部轴时按最终骨轴及插件坐标接口写入；PMX 回读时比较格式实际表达的属性，不把尾端重建差异一概判为轴向错误。

需保留参考旋转习惯的骨，将适配后的轴写入 PMX 局部轴属性并回读确认；仅修改 Blender roll，导入器可能重新选择默认 roll。显示末端用于表达端点，不替代局部轴。

源 root 不自动等同于全ての親。自动转换默认删除无权重的源结构根 root，保留子骨 Rest 并正确改接；其他专属顶层骨按用途判断。若 root 带权重、约束或驱动，先安排引用及权重处理，不能丢弃数据。MMD「全ての親」与 Root 集合保留。人体内部骨名默认使用无左右文字前缀的 `.L` / `.R` 后缀形式，标准 PMX 日文名保存在 name_j，更新顶点组、约束与最终映射；附属骨保留原名。

## 6. 膝盖与足 IK 的三层约定

膝盖的 MMD 固定轴、Blender 求解器限制和导出 PMX 的 IK link 限制分别记录。只设置 `enabled_fixed_axis` 并不能让 Blender IK 自动成为单轴铰链，也不能证明 PMX link 的 min/max 已写入。

对于确认以局部 X 屈膝的腿链，设置 `use_ik_limit_x/y/z`：X 取参考与动作验证确认的屈膝范围，Y/Z 为零范围；也可以采用经导出验证的等价锁定。左右腿分别核对符号。参考的 `mmd_ik_limit_override` 可能保留 Blender IK 数值范围无法完全表示的原始限制，结合导出选项检查其作用。

大腿和膝盖的自由度不同，不把整条链都锁成同一个轴。用连续高抬腿与回落检查膝盖离轴旋转和弯曲方向，再确认原 PMX 左右膝 link 的角度、回导入后的限制与动作。常见问题见 [bone-pitfalls.md](rig.md)。

内部骨名可保留或重命名，关键是与顶点组、驱动及约束一致；`name_j` 单独承担 PMX 日文名。左右控制骨同样使用 `.L/.R` 内部后缀，PMX 日文语义在 name_j 中明确设置，不依赖导出器猜测。

## 7. 人体完整性清单

本 skill 的默认人体配置包含：全ての親、センター、グルーブ、上下半身、上半身2、首、頭、両目；左右眼、肩臂、手首、全部手指、足、ひざ、足首、つま先，以及左右足IK親、足IK和脚尖IK。名称按上述日文规范检查，不依赖内部骨名。采用足先EX或其他扩展时将其加入清单；参考角色的专属附属骨不在人体清单内。

这是转换配置的完整性要求，并非 PMX 文件格式的强制骨数。源 VRM 缺少人体项时，根据实际关节与参考结构补齐或确认等价角色，不静默跳过。构建后、导出文件及回导入后均核对清单，确保没有缺骨、同名覆盖、末端与控制骨混用。

## 8. 骨骼集合与显示枠

集合名称和层级优先复用目标参考，按语义分配，不要求源与参考内部骨名相同。常用分类如下；参考采用其他名称时使用等价集合。

| 分类 | 骨骼范围 |
| --- | --- |
| Root / センター | 操作根与中央控制；源顶层根按实际用途判断，不仅凭 root 字样 |
| ＩＫ | 足IK親、足IK、つま先IK及其他已采用的 IK 控制 |
| 体(上) | 上半身系列、首、頭、眼与両目 |
| 腕 | 肩臂、肘腕、手部末端、对应扭转与肩辅助骨 |
| 指 | 手指各节、指尖末端及对应辅助骨 |
| 体(下) | 下半身及左右腰取消；腰控制归体(上) |
| 足 | 大腿、膝、足首、つま先、足先EX及已采用的 D 骨 |
| その他或对应附属分类 | 已确认的头发、裙摆、服装、饰品、尾巴等非人体链 |

附属骨命名通常不同。先排除明确人体与控制角色，再结合整条分支、挂接点、非零蒙皮所影响的网格区域及位置判定；头部子骨不全是头骨，骨盆子骨不全是腿骨。无直接权重的链根或末端结合相邻链判断。证据不足则记录待确认；确认属于附属骨但无细分类时可放入“其他”。

全部保留或生成骨均安排集合，包括无权重控制骨、末端骨和插件辅助骨；插件生成的 shadow/dummy 使用实际插件的专用集合，不与同名普通辅助骨混淆。参考模型自身漏配不照搬；不为凑分类生成未选用的骨。

转换分组完成后自动删除工作副本中已无骨骼的旧集合；从空叶节点向上清理完全空的分支。仍有非空子集合的组织父级保留，新分类及有效插件辅助集合保留，源骨架集合不变。清理后同步内部集合计划，避免后续验证引用已删除集合。已有工作副本可调用 `bone_collections.py` 的 `prune_empty_collections` 清理。

`bone_collections.py` 的计划为 `collections: [{name, parent, visible}]`、`assignments: {最终内部骨名: [集合名]}`、`unresolved: []`。逐骨记录分类依据在任务报告中；改名或增删后更新计划再应用。保留无关的已有集合归属，多重归属须有明确用途。

Bone Collections 是 Blender 数据，PMX 分组来自 MMD 显示枠。导出前同步公开骨分类到显示枠并保留特殊枠与表情项；回读后核对有效骨引用、逐骨集合及语义归属。插件内部辅助骨按其导出规则处理，不要求其进入公开显示枠。
