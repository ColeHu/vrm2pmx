# 骨架方法与边界

## 输入与预检

`scripts/auto_rig.py` 提供 `plan_rig`、`convert_rig`、`validate_rig`、`backtest_rig`。本分发不包含 `export_rig`。`plan_rig` 只读；`convert_rig` 创建隔离场景并在结束时恢复调用场景；综合入口 `prepare_model` 成功后切到输出场景。

按 VRM Humanoid 元数据识别实际骨名，区分 0.x 与 1.0 的拇指语义。缺映射可显式提供 `{Humanoid语义: 实际骨名}` 与 `version='0.0'/'1.0'`；不依赖模型内部叫 `hips` 或 `arm.L`。未映射的附属骨保留，不按总骨数/名称猜测删除。

自动路径需要完整基础人体映射、局部 Z 向上、静态中立输入、单个普通 vertex-group LBS 修改器、相对形态键和无反射的均匀骨架尺度。DQ、Envelope、修改器遮罩、多重蒙皮、动画/驱动/约束、绝对形态键、非均匀或反射尺度和复杂求值修改器需要单独适配。不能跳过预检硬套烘焙公式。

### 转换前自动取消修改器

`modifier_policy.py` 在预检中只读生成逐网格清单，`convert_rig` 创建单用户副本后、A-pose 处理之前执行。以下项目不再阻断预检，也不要求人工先关闭：

- `TRIANGULATE`（三角化），按修改器类型识别，与界面名称无关。
- 已识别的 `Smooth by Angle`（按角度平滑）几何节点修改器。结合节点组标准名或官方资产弱引用，并核对节点图仅含已知平滑/角度/逻辑节点；同名但带其他几何操作的节点组不自动处理。
- 已有的 MToon 轮廓预览修改器，沿用既有关闭规则。

“取消”采用禁用方式：仅在副本将 `show_viewport`、`show_render` 同时设为 False，保留修改器、节点组及其参数，不执行 Apply，不改变基础面/顶点/UV/形态键拓扑，不更改源对象开关。仅渲染开启的已知修改器同样关闭，避免后续渲染时再次生效。无需自动恢复：最终工作副本保持这些效果关闭，供用户后续制作选择。

计划写入 `rig-plan.json` 的 `modifier_plans`，执行结果写入 返回骨架结果的 `modifier_cleanup`，记录源/目标网格、修改器名称、类型、识别原因和原开关。源保全检查包含视口和渲染开关。骨架烘焙的求值比较基于**已取消这些修改器的工作栈**；不声称保留源三角化或程序平滑的最终视觉效果。法线/平滑外观由用户后续检查。

其他未知的启用视口修改器继续进入适配路径，不因用户允许取消三角化/按角度平滑就批量关闭所有修改器。转换失败只清理本次副本，源修改器状态保留。

`options` 包括：

| 选项 | 用途 |
|---|---|
| `mmd_package` | 选择实际加载的 mmd_tools 模块 |
| `apose_mode='auto'` | 默认先识别再统一到模板；旧 `template` 是兼容选项；`already_verified` 也必须实测符合目标模板 |
| `eye_mode='bones'` | 默认要求眼骨；源没有眼骨且明确保留形态键眼控时用 `morph_only` |
| `pose_roundoff_tolerance=1e-5` | 仅容许导入带来的接近单位矩阵残差，最大 1e-4；实际姿态需先适配 |
| `remove_source_roots=True` | 删除无权重结构根及空顶点组，保留 Rest；有权重的根拒绝静默删除 |
| `source_root_names` | 显式补充源结构根名称 |
| `keep_failed_for_review=True` | 保留已构建但验证失败的副本以供修复 |

## 姿态与烘焙

先执行 [姿态识别与统一](pose-detection.md)。T-pose、A-pose、中间姿态和左右不对称输入由脚本分别记录；只有符合完整目标模板的 A-pose 才跳过旋转与烘焙，其余支持的输入按实际差值校正。源 Rest 不要求一定是 T-pose，也不因归类 A-pose 就省略方向/掌面验证。

[standard-apose.json](standard-apose.json) 保存语义单位方向与掌面，是可复用制作基准，不是 PMX 格式的强制姿态。根据双臂根部、hips→head 建立角色基底，排除世界展示旋转；上臂/前臂/手按关节连线求方向，手结合食指/小指根定义的掌面修正扭转。

`apose_template.py` 按父到子计算最短弧四元数，用 `slerp(identity, delta, alpha)` 插值；正式处理 alpha=1。保留本角色骨长和比例，不复制参考角色坐标或硬编码肩臂下放角。方向/掌面验证失败时回退 Pose。新模板可通过 `capture_template` 采集，并在明确适配中应用；默认模板不被测试结果反向改写。

`apose_bake.py` 把普通 LBS 逐顶点变换同步写入基础网格与全部相对形态键，固化 Rest、保留当前求值法线，并比较烘焙前后求值误差。它会变换所有 key，但内置数值验收只覆盖当前混合状态；需要逐 key 的独立验收时额外检查，不能声称已有全量逐 key 回归。

## 构骨与绑定

先烘焙姿态，再改 Rest 方向；后者不得再次改变已绑定几何。人体内部骨名使用 `.L/.R`，`mmd_bone.name_j` 保存标准日文语义，同步顶点组、约束和形态键顶点组引用；重名不能靠 `.001` 隐藏。基础角色包括全ての親、センター、グルーブ、両目以及左右足 IK、足 IK 親、つま先、つま先 IK；源 toes 保留为足先EX并保留权重。

已有无权重控制骨按语义复用，归一化识别全/半角 IK、侧别及数字后缀，合并重复角色的引用与子级。带权重的控制候选先报告，不直接删除。

下半身由腰部向骨盆，保留腿和附属骨支点。脚尖由实际加权脚部几何确定：足 IK 水平向后，足先EX水平向前；足先EX的 head 保留原 toes 关节，tail 水平向前略超过つま先、つま先 IK 的共同头部。腿两节 IK、脚部一节 IK，膝单轴屈曲、其他轴锁定。向后的预弯可在实测腿平面中修复，保持髋踝支点、骨长和网格；明显侧弯的特殊腿型由回测诊断。

腰及左右腰取消默认按 [腰与腰取消控制](waist.md) 创建/复用：以本角色髋宽搬运参考相对位置，上下半身共同挂腰，左右大腿经腰取消继承下半身，以原生 `-1` 付与旋转抵消腰传向腿的旋转。保留原髋关节支点与蒙皮，验证静态结构及真实动作。

骨集合覆盖全部骨，显示枠独立创建，不把 Blender 集合当成 PMX 显示枠。默认在 A-pose/标准命名之后按[腕与手扭转骨](arm-twist.md)建立左右腕捩、手捩和各三根分配骨。该步骤主动改变副本局部蒙皮，保留其他骨的份额及形态键遮罩；再建立原生付与旋转、集合和显示枠。附属骨保留原名和链，不擅自扩展 D 骨或其他专属控制系统。

## 诊断与局部修复

`backtest_rig(name, output_dir)` 按腿长采样连续抬升/回落、前后和侧移，测试后恢复姿态；记录膝离轴角、向前屈曲的有符号投影、踝跟随误差、脚部额外轴向扭转、连续性及回落一致性。到达目标且离轴角为零，仍可能向后弯，不能只看角度绝对值。

失败先读 `repair_queue` 和最差采样，核对 Rest、真实轴向、膝弯曲侧、脚尖目标和重复约束。已有 `repair_knee_bend`、`repair_export_axes` 与 `restore_rest_checkpoint` 可用；`repair_export_axes` 名称沿用既有工具，只修复 mmd_tools 轴元数据并写检查点，不执行文件导出。mmd_tools 局部轴采用 XZY 约定，不能把 Blender XYZ 向量原样写入。

一次修复无效就恢复检查点，继续诊断。脚部扭转筛查默认 15°，不代表服装外观已验证；不得仅提高阈值或改报告状态消除异常。
