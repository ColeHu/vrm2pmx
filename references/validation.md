# 验证与人工接手

## 本阶段验收

检查报告与真实 Blender 数据，不能只看脚本没有抛异常。

| 范围 | 通过条件 |
|---|---|
| 副本与源保全 | 独立工作场景，骨架/网格 data 单用户；源骨架、顶点、权重、形态键、UV、面分配和基础材质指纹不变 |
| 修改器取消 | 副本上的三角化、已识别按角度平滑、轮廓预览视口/渲染均关闭；保留数据和参数，不 Apply；源修改器开关不变；未知启用视口修改器不静默关闭 |
| 人体结构 | 基础骨完整、标准名唯一；父级无环、骨长有效；附属骨保留；集合覆盖、显示枠引用正确 |
| 腰与腰取消 | 三根控制骨唯一，布局按目标髋宽适配，层级/轴/通道锁定/无权重正确；取消倍率为 -1，动作与实测参考响应一致；下半身独立旋转及恢复后的脚 IK 通过 |
| 姿态识别与烘焙 | 记录源 T/A/中间/左右不对称分类与角度；目标模板已匹配时保持网格及全部 key 原样；需要校正时模板方向/掌面及当前形态键混合状态的烘焙求值误差通过，全部相对 key 参与变换；未逐 key 独立检查则明确保留限制 |
| 腕捩/手捩 | 左右主骨与分配骨共16根，主骨尾与下级头重合并用 BONE 连接，分配骨竖直等长并用 OFFSET 连接；层级/固定轴/倍率/隐藏正确；权重计划与写入一致、总量不变、其他骨份额保留；四根主骨 ±30°/±60° 原生动作及姿态恢复通过；人工检查衣袖/关节外观 |
| 腿/脚动作 | 膝单轴且朝前，连续抬升/回落、前后侧移无异常；踝跟随、脚部轴向扭转和连续性通过 |
| 材质 | Diffuse=(1,1,1)、Specular=(0,0,0)、Ambient=(0.5,0.5,0.5)；Alpha、双面与记录一致；活动 mmd_tools 的 FnMaterial.get_texture 可读 IMAGE 主图及存在文件；面分配有效，命名 UV 与导出活动 UV 一致 |
| 效果边界 | 描边关闭且宽度为零；Sphere 模式 0；Toon 未分配；无新 Sphere/Toon/描边遮罩或物理制作 |
| 交接 | 骨架+材质完成才用 `prepared_for_manual_edit`；仅骨架为 `rig_prepared_materials_pending` 并明确材质未做；`pmx_exported=False`；工作对象/场景和报告路径明确 |

姿态识别、采用动作和最终 Rest 误差在返回骨架结果的 apose 中；modifier_cleanup 和骨架证据保留在返回值，综合阶段结果由 prepare_model 直接返回。不生成 preparation-report.json、rig-report.json、pose-detection.json 三个独立文件。rig-backtest.json 与 material-conversion-report.json 等其他记录保持现有行为。完整入口对源执行包含网格/形态键/UV/基础材质与修改器视口/渲染开关的指纹比较；骨架单独入口的源检查较窄，不把它描述成全材质审计。

失败输出用 `needs_repair`，保留独立副本和修复清单；检查点、修复与复测按 [骨架方法](rig.md) 执行。修复现有副本后可分别运行 `backtest_rig` 和 `validate_materials`，以新报告说明已通过的范围；不要重烘焙整个副本或仅手动修改失败状态。

## 人工接手

交付时简明说明工作场景、骨架、网格、贴图和报告位置，以及是否保存新的 `.blend`。用户可在 Blender 继续调蒙皮、服装、手指、附属链、材质颜色、表情、显示枠及所需扩展骨，再自行选择导出比例、路径和 PMX 导出设置。

`save_work_copy(new_path)` 仅接受不存在的 `.blend` 路径，通过 `bpy.data.libraries.write` 写出当前工作 Scene 及其依赖，保留外部贴图的绝对引用。它不改变当前项目的保存目标，也不调用全文件 `save_pre` 回调；VRM 插件的此类回调可能在 `save_as_mainfile(copy=True)` 时迁移源对象。产物是场景数据型 `.blend`，不复制当前窗口布局：重新打开时 Blender 会创建/选中空白场景，需要在 Scene 选择器切到报告中的工作场景，也可通过 Append Scene 载入该场景。贴图仍需随产物保留。不要把保存步骤改回可能触发源迁移的全文件保存。默认不保存，直接在当前 Blender 工作场景中交接。

本阶段不做 PMX 导出/回读。`pmx_roundtrip`、目标引擎材质观感、特定服装动作、全部形态键独立审计、完整 VRM 表情和物理仍为后续检查事项。不能用 `PMX-ready` 或“兼容性已完整验证”代替准确的“Blender 内制作准备通过”。

材质维护测试额外覆盖有效图片输出、Principled、单位 Emission、透明混合与反向遮罩，命名 UV 错配拒绝，固定颜色，以及实际 mmd_tools 导出器材质写入函数在内存中生成非负主图索引。测试删除 MMD 主图时必须检出失败；“仅骨架”状态也必须明确显示材质待处理。

人体内部名称检查 `.L/.R`，PMX 日文语义分开检查；足先EX的 head 必须保留原 toes 关节支点，tail 必须水平向前略超过同侧つま先、つま先ＩＫ头部。`tests/toe_pivot_names_blender.py` 对照独立 LBS 验证实际 ±30° 蒙皮、回零、后缀引用、IK/扭转/腰取消与显示枠。

## 维护测试

分类完成后清理旧空集合：测试覆盖空叶、全空父子分支、重新分类后变空的旧集合；有非空子集合的组织父级保留。源集合保持不变，工作副本的保存计划与实际集合一致，后续回测不引用已删除集合。

主机 Python：`python -m unittest discover -s tests -p 'test_*.py'`，验证线性颜色、纯色主图和 Alpha 三种模式。Blender 集成测试使用 `tests/blender_smoke.py` 的 `run(OUTPUT_DIR, ACTIVE_MMD_PACKAGE, HOST_PYTHON)`，要求 VRM/mmd_tools 已注册。使用隔离后台进程，勿在用户生产场景直接运行测试。

集成测试生成合成人体和材质，覆盖 VRM 0.x/1.0 的 T-pose、已固化 A-pose、中间姿态、左右不对称输入，验证源数据保全、统一后 Rest 模板匹配及 IK 回测；已符合目标的 A-pose 重复处理不改变网格和形态键。每组包含三角化、仅渲染开启的三角化和按角度平滑，检查副本取消、源开关保留；另外检查未知修改器拒绝及取消后转换失败的回滚。腰测试覆盖参考相对位置、躯干随动、腰取消、下半身独立旋转、已有控制复用、重复合并、带权重候选拒绝及腰取消约束/倍率损坏的检出。另覆盖材质面分配、Alpha、颜色、无轮廓/Sphere/Toon、人工改坏材质的检出、纹理 worker 失败时槽保全，以及无 PMX 文件产生。合成测试不等于每个真实角色的服装变形验证。

扭转维护测试见 `tests/test_arm_twist.py` 与 `tests/arm_twist_blender.py`，覆盖分配区间/端点、混合关节权重、四骨影响溢出拒绝、真实蒙皮与独立轴角 LBS 公式比对、隐藏分配骨及主骨显示枠。

默认原图策略由 `tests/original_materials_blender.py` 检查四种材质来源、全流程默认分支、原图绝对路径与文件哈希、固定颜色、内存导出纹理索引、幂等、缺图拒绝和赋槽后失败回退；原来的烘焙回归显式传 `texture_policy='bake'`。
